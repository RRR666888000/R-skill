# 维护与版本

可编辑源是仓库根目录的SKILL.md、references及可选agents元数据。不要单独修改dist单文件或ZIP；它们由同一份源生成。

维护时运行：

```sh
python3 scripts/build.py
python3 scripts/validate.py
```

维护脚本要求Python 3.9或更新版本，仅使用标准库。普通创作不依赖Python；目录版在完整成稿需要时长估算时，可选运行`scripts/estimate_duration.py`，不能运行则明确给粗估。构建验证入口、相对引用、同源文件、ZIP根结构、时长脚本算术及跨路径迁移；不自动给创意质量打分。

改行为规则时保存具体失败输入、初次输出和判定理由，选择相邻案例回归。每例记录版本、宿主/模型（已知才写）、载入形式、是否延续前文、首次结果与修正结果。不要只发布成功样例，也不因一个结果反复增设全局禁令。

版本0.5.0在0.4.0的全文整合基础上，完成公众文档与导入包、本人风格授权与无口播入口适配、事实关系/时序和更新素材边界收紧。依然默认方向与骨架，不强制单一立场、固定结构或商业化。初稿与回归记录见tests。

收到反馈先判断是素材缺口、方向、推进、语气、形式还是受众偏差。事实核对不可用词表测试替代；实片与发布结果也不能用文字审计替代。来源知识不要求每次重读，私人课程或用户作品不加入公开测试。

0.5.1聚焦创意效用：比较正文差异、保留有条件的探索、让反馈进入所选骨架、围绕观看承诺判断必要材料。对照结果有改善也有持平与退步，按具体失败做局部修正；不宣称所有任务更好，也不撤回既有Kimi保真失败。见tests/creative-051。

0.5.2聚焦非事实类可用性：用固定交付状态阻止“骨架”漂成全文或制作配套，收窄与账号/制作类技能的自动触发重叠，加入可复算的时长脚本，并把跨宿主验收拆成文件、发现、调用和行为四层。事实保真规则沿用0.5.1，本版不以解决既有P0失败为目标。
