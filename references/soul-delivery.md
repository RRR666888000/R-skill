# 灵魂问答：从六问到行动

六组问题的内容和顺序保持不变。本文件在六组完成后、需要暂停或移交、收到真实反馈时，或用户明确授权代入推演时使用；不是第七套问卷。这里的交付、证据和复盘规则是本技能的扩展，不冒充原作者逐字方法。

## 1. 整理一份可复用的需求底稿

从已有答案提取，不再让用户重复填写：

- 目标：这次要交付什么，让谁在什么场景下采取什么行动；不默认目标都是成交。
- 情境画像：使用者、决策者、付费者或资源投入者；触发事件、想得到的结果、替代办法、犹豫点。年龄、性别、收入未知就留空或写未知，不以想象填满。
- 需求链：现状 → 期望 → 差距 → 替代办法与代价 → 采用/不采用的理由 → 最可能失效的条件。
- 证据表：ID、来源/日期、原话或行为、对象与场景、支持什么、不能证明什么。区分用户明确陈述、观察记录、推断、待验证假设；生成的画像与问题不算新证据。
- 决策问题：按五阶段组织，先处理最阻断本次目标行动的少数问题；保留未解项和下一步取证。
- 搜索词线索：由具体问题生成“对象/身份 + 情境/任务 + 顾虑/替代”的候选词，标明想找谁、想证实什么。无搜索结果时只叫候选词，不声称有流量或搜索量。
- 可借鉴动作：来源、机制、适用条件、不能迁移的部分；未知对标明确留缺，不凭空补账号。

从本次目标提出一条可观察的完成标准，例如选定一个可测试的人群、写出可用回答、完成一次试用；标为用户已确认或 AI 建议。任务目标已清楚时不为此加一轮审批。预计问答负担与实际效果尚未测量就保留未知，不能以六问全部填满作为成功。

需要暂停、用户要求移交或换 Agent 时，提供一段可复制的续接摘要：议题与目标、已覆盖组/下一组、用户已确认答案、证据来源与可访问性、假设和缺口、当前交付状态、最新产物、下一步。后续沿摘要续接，不重问已有答案。技能安装只迁移方法，不自动迁移会话、附件或私人资料；跨环境无法读取的证据标待提供，不能假装已经读取。未经授权不把项目资料写入公共技能或公开仓库。

完整研究可展开，简单任务只展示影响当前交付的部分。用户没要求长报告时，给关键判断和具体产物，不把六张表全部倒出来。

需要外部调研时，连接“问题 → 候选搜索词 → 实际样本 → 意图/身份判断 → 对标结构 → 可执行动作”。核对检索对象：面向经营者需角色和任务限定，面向消费者不机械排除消费者。抽样覆盖已采用、未采用与放弃者，兼看普通和负面材料。统计去重、说明人数/评论数/对话数、分母与时间，多标签占比可能超过 100%；没有计数不称最高频，小样本不外推市场。能检索就执行必要检索；访问不到则给具体取证办法和缺口，不编结果，也不因缺对标卡死低成本试验。这里只是本篇的取证桥接，不宣称掌握作者未读取的后续关键词矩阵方法。

## 2. 把购买理由、顾虑、证明接到具体动作

对优先问题串起：这个人想得到什么 → 为什么犹豫 → 我们能如实证明什么 → 用什么产物回答 → 下一步如何观察效果。缺证明时给取证动作或限定表达，不把承诺当证据。

按本次任务交付至少一个可直接使用的结果：

| 任务 | 具体产物 | 观察什么 |
|---|---|---|
| 内容 | 对应决策问题的方向、骨架或成稿，服从凌酱当前交付状态 | 目标受众是否理解、继续看或采取目标行动 |
| 话术 | 可直接说出口的回答，配已有证明和适当下一步 | 顾虑是否被接住、对方下一步是否更明确 |
| 新品 | 优先情境、需要满足的条件、最小样品/服务验证方案 | 真实试用、选择、支付或放弃的原因 |
| 新业务 | 最值得验证的假设、交易与交付路径、小规模验证动作 | 能否触达、交付，是否出现实际需求行为 |
| 落地 | 动作、负责人或待定负责人、交付物、期限或建议期限、验收条件 | 具体阻塞是否减少，交接或执行是否完成 |

用户明确限制本轮只要一句/一段/某个字段时，最终只给要求的产物；分析与验证线索保留在内部，不借增强流程扩大交付。产品做不到的要求写入产品缺口，不靠更强的话术掩盖。

## 3. 积累原话和可迁移结构

原话库记录来源、上下文、意图、可用位置和公开使用条件。自己的概括标为概括；未经允许的私人表达不放进公开文案、公共技能或仓库。真实原话比抽象卖点具体，但不代表已经取得对外引用许可。

结构库记录：适用人群/场景、要回答的问题、入口、展开、证明、行动引导、不可迁移条件。只迁移结构与机制，用自己的材料重写；不复制独特文案。仅有标题或关键词的材料是线索，缺完整正文/视频结构时不能充当完整母本。

## 4. 用真实反馈修正

为最关键假设设计一个最小验证：假设、变化项、比较条件、观察行为、投入与时间边界、保留/调整/停止依据。未知基线时先建立基线，不编造行业标准、转化率或成功阈值。

反馈回来后比较原判断与实际，分别检查人群、需求维度、触达偏差、使用门槛、证明可信度和交付能力。既看购买/采用者，也看犹豫、未采用、退货或中途放弃者。优先修正被证据推翻的部分，保留仍成立的答案；不只换文案，也不自动认定找错了人。

把人群与想完成的事交叉看：同一人群可能有不同购买理由，不同人群可能为同一需求而来。新行为与旧画像不符时，同时保留“原需求维度遗漏”和“触达样本偏差”等解释，列出区分它们所需的证据。购买、安装、使用、完成任务、再次使用是不同信号；没有后续行为，不把“购买/安装完成”当价值兑现。无新证据时更新状态为待验证，不用多跑几轮提高置信度。

## 5. 经授权的产品自测

只有用户明确要求代入、自测或模拟时，才允许 AI 基于已知材料走完六组；普通调用仍逐组等用户回答。开头标明这是推演，用户原话、推断、未知分开，不伪装成真实用户访谈或市场验证。

每轮都保留六组对应的输入/判断、最有影响的缺口、修订动作及复测结果。重复读取同一材料不会增加独立证据；没有新反馈时只能检验逻辑、覆盖和执行性，不能声称产品已经满足用户或卖得动。通常两轮，用户要求或存在明确缺口时第三轮；每轮只补具体缺口，不无限加模块。没有授权修改技能时，只输出建议。

需要具体采样步骤、从样本寻找对标或核对完整调研交付时，按 soul-research.md 执行；完整研究交付状态与证据验证状态分开报告。
