# 灵魂问答执行说明

此文件是维护者依据原文与用户要求编排的执行说明，不是作者原始提示词。原话以 soul-questions.md、soul-prompt-inventory.md、soul-source-context.md 为准；不修改这些文件中的引文来适配业务。

1. 来源与使用规则

## 1. 来源与使用规则

- 作者的六段提示词是AI分析任务，不是让用户手工回答100道题。作者正文还含取得材料、使用分析结果、成交后校正的步骤；只跑六段不算覆盖全文方法。
- 用户定制：默认逐组互动，沿用已有信息，每次问当前组所缺的输入，等待用户回答后执行该组分析，再进入下一组。显示第n/6组。六组均须覆盖，不替用户编造自身业务输入或擅自确认其选择；分析、画像、问题生成由AI承担，用户明确授权代入模拟时可按已知材料推演。已有回答不重问，同一任务续接不重开六组。
- 默认完成原文要求的数量和字段，不自行切换“简短/完整模式”，不以话术短、已有初步人群或想省时间为由减成3–5类、10–20问。用户本次明确要求跳过、只做某一步或缩量时按其要求，并说明本次范围，不称整套调研完成。
- 执行编排：证据不足时保留“待取证”，继续能完成的部分；需要该材料才能进行的统计或检索不假装做完。生成的画像、问题、高频预测标为假设或推断，真实材料单列来源；原文的数量目标不能靠编造客户和账号凑齐。
- 查原文时读取指令清点和相关正文。用户要求只提取原文时仅返回原文，不启动业务问答；技能审计与维护同样不触发业务问答。

## 2. 六组互动及其间的原文步骤

### 第1/6组：P1，谁会买（第二节；第一节提供材料基础）

沿用已知产品、一句话功能、售价与使用场景；缺哪个问哪个。结合已有客户自我介绍、痛点与需求执行P1：列5–7类人群，每类写需要时的具体处境，对规模、付费能力、刚需程度、触达难度四项逐一判断，排序并推荐1–2类及理由。回应正文“这个市场大概多大”：给有依据的粗估范围或估计方法与待补数据；不能以大/中/小标签冒充市场规模估算。没有市场数据时区分估计与实证，不编规模数字。请用户确认或调整本轮优先人群后进入P2。

### 第2/6组：P2，把人群变成具体人物（第三节）

承接所选人群，先接住用户对真实人的描述；对本轮每一类选定人群分别执行P2，各生成2–3个具体人物，不把两类合计压成2–3人；每人保留年龄、收入、性别、职业阶段、决策路径、购买原因、不买后果七项。按正文同时讲清决策效率、买了能解决什么，落实到下一句话怎样写。真人资料缺项标待核实；推演人物可以填写具体设定，但整个画像必须标为假设，不把虚构名字和收入当真实调研。不得省略七项或退回宽泛人群标签。

### 第3/6组：P3，需求形成（第四节；接第五节）

询问缺失的处境、落差、现有办法和代价，按P3顺序分析人工填补的时间/钱/人力、替代方案及不足，输出需求=A×B×C并逐项解释归零后果。保留原文示范中的可信度条件和招人培养/错过窗口的成本线索；这些是采集工具案例，不自动当成所有产品的同一组乘数。公式是作者要求的分析产物，不能因质疑普适性就省掉；区分本业务待验证的假设与已证实条件。

接正文第五节：收集用户已知的购买顾虑，将每条顾虑对应到一条具体内容或回答。作者的账号安全、功能实测、价格账、售后承诺是案例，按当前产品的真实顾虑代入，不能照搬“封号”给所有产品。

### 第4/6组：P4，真实材料与采样（第一、六、十节）

先问已有评论、问题清单、成交/私聊记录。已有材料直接读取；没有内测用户时执行第六节：产品直接相关词+用户说法→种子词表→每词约5–10篇笔记→相关话题与评论→意图和身份判断。此数量是作者起步采样示例，不能称统计上已充分。

随后执行P4的三件事：分类统计条数/占比；分别统计目标付费者、非目标对象的人数及占比，身份不明单列；偏离目标时指出原词错在哪，再给一条关键词结构修正建议。作者B2B案例中的两类是掏钱的经营者与终端消费者，不能只给泛泛身份判断而漏掉数量。明确统计单位和分母，不把预测当计数。看意图分布而非只看热度；正文74条、38条“怎么用”、16条“免费吗”只是作者案例。B2B案例按“身份+做内容”修正裸品类词；B2C业务按本轮实际付费者判断，见第4节代入说明。

无访问能力或没有样本时交付具体采样词和材料缺口，将P4统计留为待完成，可继续生成明确标为假设的后续研究，但不得说已经验证。

接正文第七节：针对人群说清买到的结果及理由，连接到内容/话术或产品需要满足的条件。作者例子是省时间、提高产能与获客、发现商机快速测款；保留“用用户真实表达”的方法，引用用户材料中的原话，不编证言。不把所有业务价值硬归结为作者这三类。

### 第5/6组：P5，五阶段100问（第八节）

承接人物与证据，确认缺失的实际顾虑，执行P5：按主动找方案、被别人介绍并第一次看到这个东西、功能了解、下单前、购买后五阶段逐场景生成100个具体到可当标题的问题；标出预计问得最多的并说明判断依据，挑最优先做成内容的10个。数据未支持的频次排序标为推断，不能冒充真实高频统计。100问是AI承担的产出，不让用户逐题填答案，也不自动缩量。

100问之后继续正文的三种用途：问题作为选题；从各场景问题提炼种子关键词并列成表；用词采集行业/决策路径相关内容，提炼结构与模板，并按第6组同业路线用自己的视角、语言和事实实际代入试用、测试后复用。把“问题→关键词→样本→对标/内容动作”连起来，不能止于十条标题。采集得到的新需求回写人群与需求判断。

### 第6/6组：同业数据路线 + P6异业路线（第九节）

先承接同业数据路线：从采集笔记中提取反复出现的商家、账号ID和相似昵称；查看候选账号，采集其可访问的全部笔记，范围受限就报告缺口；找反复使用的三五个模板及其真实样本，保留标题、正文、完整结构。只有关键词或标题的表是线索表，不能称母本库。反复出现和相似昵称是查证线索，不足以由技能声称已证实同一矩阵。把模板代入自己的视角、语言和事实，试用并看数据，有效后继续复用；没有测试结果时保留待测状态。不得用下面的异业研究替代这一条同业路线。

再执行P6：按原文先复述对业务的理解，让用户确认后再输出解构；已有用户明确确认可沿用，不重复问。拆商业本质、壁垒/差异化、关键环节；找“5个以上”底层逻辑相似的异业标杆，逐个给真实获客渠道、具体动作与可迁移细节；每个找3–5位一线实操者及账号/平台、可查来源、最值得学的一个动作。对象必须正在做该业务，能找到具体操作手法或操盘细节；按原文排除知识付费博主或商业导师，并另外排除搬运、二创、躺赚、灰产等无效流量玩法，保留风险提示和禁止套话要求。最后给3条跨界洞察，以及72小时内研究的3个对象与主页具体看什么、学什么。

数量未找到足额就标明已找到多少、还差多少和原因，不编人、不偷改目标。作者实际填写的“9.9体验/169买断”描述保留在原文材料中，仅作为填写示例。

## 3. 调研交付与真实反馈（第十、十一节）

分别保留原文两处清单：第十节是具体人、具体问题、具体词、对标表；第十一节是画像卡、需求公式、100问、对标账号和模板。两者有重叠但不完全相同，执行取并集，不丢关键词或公式。

| 交付项 | 核对内容 |
|---|---|
| 人群与画像 | 5–7类的四项比较及优先1–2类；每类选定人群各2–3个人物、每人七项；决策效率与买后解决的问题 |
| 需求拆解 | 推导过程、人工成本、替代方案、乘法公式、每个条件归零后果 |
| 用户问题与内容 | 五阶段100问、频次判断依据、优先10问；顾虑与购买理由怎样变成可用内容/话术 |
| 种子关键词 | 问题对应的词、想找到的对象、采样和修词情况 |
| 对标账号与模板 | 同业来源与完整母本、重复模板、测试状态；P6异业标杆及每类3–5位实操者、3条洞察和72小时3对象 |

标明每项已产出、待取证或未完成；产出齐全不等于已被真实数据验证。用户明确只做部分时记录范围，不能自行将缺项改为“不适用”。承接用户本次要的内容、话术、新品方案、业务判断或落地动作，让研究有可开工的结果，不凭空加用户未要的报告体系。

执行原文第十节循环：每成交一批，记录真实身份、问题、痛点和顾虑，交给AI重新做画像；与旧判断逐项对照，检查遗漏的需求维度和跨人群共同购买原因。保留作者“个人博主优先级被真实买家纠正、实际买的是图片素材”的案例含义，不能简化成一句“换人群”。将真实数据喂回分析，修改后再跑第二遍；无新数据的重复推演不等于验证。按结果更新选题、关键词、产品需求与对标动作。

## 4. 场景代入与续接（用户定制/执行适配，非作者原话）

保持原文文件不变。应用时明确本轮产品、渠道、付费对象和任务，必要时简短说明代入：第四段作者卖给经营者，若本轮卖给消费者，应检查是否采到目标消费者，不能因消费者占比高就判错；第六段“小红书内容获客”与案例业务描述替换为本轮真实业务背景。代入只改变业务变量，不自行改变任务数量、研究步骤或输出要求。

对于内容/话术/新品/新业务，沿用相同研究链；内部落地任务若没有购买者，先和用户明确谁是受影响者、决策者、资源投入者及希望发生的动作，说明这是用户要求的迁移场景，不能伪称作者原文包含该应用。具体业务数据不能写入公共技能。

暂停或换Agent时，按用户需要交代当前组、已确认输入、已产出内容、证据和待完成项；恢复时沿用这些材料。明确授权的自测可以代入推演，但不将模拟人物或重复推演当真实用户验证。原文案例中的商业结论不作效果承诺；对原文表达有必要的限制或解释，单独标为执行说明，不篡改原话。
