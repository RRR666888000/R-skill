# 0.5.2 非P0可用性与路由验收

日期：2026-09-12。最终入口版本`0.5.2`，`SKILL.md` SHA-256为`85020a4cc4e6dc57c1213cf0934690ae74580f667718593c60ec95b3d6c607be`。

本轮维护者明确决定不处理P0事实保真问题。因此历史中的补造经历、商品属性和虚构外部核查仍按原记录保留，但不纳入本轮放行条件；本报告只回答交付范围、继续状态、算术、路由、安装与降级说明是否达到可用。

## 环境与判定方式

- Codex CLI：`gpt-6-astra`、`gpt-5.6-sol`、`gpt-5.6-terra`、`gpt-5.6-luna`，均为隔离新进程。
- Claude Code 2.1.177：配置模型`kimi-k2.6`，使用显式`/lingjiang-content`；这不是Claude模型测试。
- 行为题按首次输出或保留失败后的定点回归人工检查；运行成功信封不等于内容通过。
- 路由题从事件日志确认实际读取的`SKILL.md`路径，不根据回答口吻推断。
- 每个模型/用例样本量很小，不换算通过率，不宣称所有宿主或未来版本同样表现。

完整成稿的时长分支中，Kimi因Claude Code的`dontAsk`权限策略未能运行脚本，但明确标成粗估并继续交付；这属于可用降级，不记录成工具执行成功。目录版新增标准库脚本后，静态测试覆盖明确单位复算、中文标点排除、非法语速报错及英文占比较高时的警告。

## 路由结果

五类隐式请求的期望为：

| 请求 | 凌酱 | 内容编导 |
|---|---|---|
| 一条视频怎样讲、只要文字方向/骨架 | 读取 | 不读取 |
| 账号定位、三个月栏目与团队分工 | 不读取 | 读取 |
| 一批直播素材分类和混剪 | 不读取 | 读取 |
| 只把视频转码，不做内容判断 | 不读取 | 不读取 |
| 只分析经营表，不做内容创作 | 不读取 | 不读取 |

Astra与Sol在候选目录对上述五类全部符合；Luna与Terra在0.5.2正式安装后对上述五类全部符合。早期候选测试中，Sol曾因两个描述都写了大量负面排除词而双触发；改为互斥的正向任务描述后消失。Terra和Luna曾优先读取用户目录旧0.5.1，故候选结果未冒充新版本表现，安装后才重新计入。

Claude Code当前配置下，目录可发现不代表自然语言一定隐式选择该Skill；显式`/lingjiang-content`已验证。文档因此把“文件、发现、调用、行为”拆成四层，不把可读文件写成已调用。
