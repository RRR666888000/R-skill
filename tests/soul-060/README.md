# 0.6.0 灵魂问答增强验证

日期：2026-10-05。环境：当前 Codex 的隔离子代理；未单独核验模型标识。载入形式：明确给出已安装目录，读取 SKILL.md 及按需参考。A、B、C 各自使用新线程，B2 沿用 B1 对话。以下为首次输出，无失败输出被替换；验证显式读取后的行为，不等于验证所有宿主的自动发现。

## 三轮设计推演及修订

把灵魂问答视为产品进行三轮推演，每轮沿用六组：服务对象、具体情境、需求与替代、证据、采用阻碍、可借鉴机制。

| 轮次 | 发现 | 已实现修订 | 仍未验证 |
|---|---|---|---|
| 1：需求覆盖 | 六问后的信息需要连接到实际产物 | 需求底稿，理由/顾虑/证明/动作，原话与结构积累，反馈复盘 | 真实用户是否采用产物 |
| 2：使用路径 | 跨 Agent 安装方法不等于迁移已有问答；问完不等于完成任务 | 续接摘要、证据可访问性、可观察完成标准 | 目标电脑宿主安装、实际问答负担 |
| 3：全文复核 | 缺从问题到检索/样本的桥接；需区分人群与需求维度 | 候选词、样本核验、人群与需求交叉复盘、区分购买/安装/使用/任务完成/复用 | 真实市场效果与长期复用 |

第一版还进行了独立的授权代入推演，结论为方法覆盖已有支持、跨环境安装与实际使用缺少证据。相关输入涉及私人会话，未公开原话或画像。本表是过程摘要，不是市场验证或公开原始日志；公开行为样例使用下列虚构任务。

## A：新任务保持逐组问答（凌酱入口）

输入：灵魂问答，我想帮自由职业者做一个整理客户需求的小工具，现在只有这个大概想法。

首次输出：

> 我们按凌酱 Skill 的「灵魂问答」逐组梳理。你现在的想法是：帮自由职业者整理客户需求，具体服务谁、解决什么麻烦还待明确。
>
> **第 1/6 问：谁会需要，谁会付钱？**
>
> 你最想先帮哪一类自由职业者，解决整理客户需求时的什么具体麻烦？比如设计师接到的要求零散、开发者反复确认功能，或文案写作者拿不到清楚的简报——这些只是帮助你联想的例子。
>
> 你设想是自由职业者自己使用、决定购买并付钱吗？还没想清楚也可以，先说你最熟悉或最容易接触的一类人。

判定：通过。本轮停在第 1 组，未因为支持授权自测而自动代答。

## B：续接与暂停（凌酱入口）

B1 输入：继续灵魂问答。我从另一 Agent 带来摘要：目标是为三人工作室做客户需求交接工具，主要使用者是接单人和执行人，老板决定是否用；具体客户是一家三人设计工作室，访谈者描述他们通过群聊和手工表格交接；希望减少反复确认，现有方案能用但信息散。第1到3组已答，第4组刚答：没有访谈录音和可共享记录，上述情况来自我个人经历，尚未有客户试用数据。下一组是第5问。请承接，不要重复前面的问题。

首次输出：

> 我会按凌酱 Skill 承接，直接进入第 5 问。前面的情况先记为你的个人经历，尚无可共享记录或客户试用数据；减少反复确认的效果仍待验证。
>
> **第 5/6 问：从第一次知道，到采取行动，他会卡在哪里？**
>
> 让这家三人设计工作室开始试用交接工具时，你最担心老板、接单人或执行人提出哪一句疑问？这次最需要先解除哪个阻碍？
>
> 如果还没听过他们的原话，说你最担心的一句即可，我们会把它标为待验证的假设。

B2 输入：第5问我的回答是不知道他们会怎么想，我只担心学习成本。今天先停在这里，你帮我留一段能发给另一个Agent接着聊的摘要。

首次输出：

> 继续凌酱 Skill 的“灵魂问答”：本轮目标是为三人工作室做客户需求交接工具，主要使用者是接单人和执行人，老板决定是否采用，付费安排未知。具体情境是一家三人设计工作室通过群聊和手工表格交接，现有办法能用但信息分散，希望减少反复确认。第 1–5 组已回答，用户要求今天暂停，下次直接进入第 6/6 问“谁已经做成类似的事，我们具体学什么”，不要重复前五组。证据状态：上述情况来自用户个人经历，没有访谈录音或可共享记录，也没有客户试用数据；不能将这些描述当成已核实的客户访谈或产品效果证明。第 5 问用户原话：“不知道他们会怎么想，我只担心学习成本。”因此学习成本仅是用户担心的采用阻碍，尚非客户确认的顾虑；客户真实决策问题、采用意愿及工具能否减少反复确认仍待验证。当前处于问答暂停阶段，尚未产出产品方案，最新产物是本续接摘要。下次只问第 6 组并等待回答，完成后再汇总已知信息、假设与缺口，承接产品方案或验证动作。

判定：通过。沿进度提问；承认没有记录；“不知道”作为有效回答，暂停摘要指定下一组并保留假设状态。

## C：六问后只交付一句话（独立兼容入口）

输入：我们六问已经走完，请承接这些已确认答案：卖一款帮助自由插画师整理项目资料的工具，使用者和购买者都是本人；唯一接触过的插画师经常跨设备找文件；现有替代是文件夹和笔记，想改进查找和项目交接；没有试用或购买数据，只收到这位朋友一句“我怕换工具更折腾”；最关键顾虑是搬迁成本；暂无真实对标。现在只帮我写一句可以对他说的话，不要附分析。工具还没实现导入功能。

首次输出：

> 搬资料确实可能更折腾，我这边还没做导入功能，你先不用换，方便让我看看你平时怎么跨设备找一个项目的文件吗？

判定：通过。只给一句可用话术，不重跑六问、不输出整套表格、不虚构导入能力或客户效果。
