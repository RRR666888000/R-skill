# 0.5.1 创意效用：三题、一次反馈与局部修正

本轮关心方向是否有用、骨架能否接着写，同时保留事实底线。不是播放量或爆款测评。输入均为[合成测试素材](cases.json)，没有私人课程或真实业务原文。

## 方法与环境

0.5.0为基线，0.5.1为候选。两个独立Codex子Agent分别只读各自版本及同样的三题，未提供另一组答案、缺陷或预期结果。每组C1初稿保存后才读取追加反馈，C2/C3不串用事实；同组共用Agent上下文，不冒称逐题独立进程。底层模型精确ID未单独报告。

第三位评审仅获得输入与标为A/B的首稿，不知版本。评审写完后揭示A=0.5.1首候选，B=0.5.0。详见[盲评原文](blind-review.md)、[方法源哈希](source-hashes.json)。这不是随机实验，也没有推算总体胜率。

Claude Code现有配置模型kimi-k2.6；两次独立进程、完整单文件输入、禁用任务文件读取工具。只测C2，未测其他题；这是文本方法调用，不是本轮重新认证原生发现，也不是Anthropic模型测试。

两次均正常返回，但事实与方向验收未通过。本轮没有以重试挑选通过结果，不能宣称修复该模型的不遵循问题。

## 根据盲评的局部修正

在development中修正两项决策：反馈必须落实到选定骨架的段落任务/内容重点/揭示顺序；推荐先兑现最重要观看问题，不能把必要证据降为可选装饰。只对受影响的C1反馈和C3进行一次独立复测，其余首次结果仍保留。

独立新Agent只获得当前方法、C1原始请求/此前初稿/追加反馈及独立C3请求，不读旧评审或预期答案。只生成一次，原稿保留：

- [C1反馈定向复测](refined/C1-followup.md)：所选骨架从奶奶评价进入，把正文转成“认对字/评价字的样子”的对照；另一个探索方向明确需要用户补原稿上的真实细节。没有替奶奶解释反科技或怀旧。
- [C3定向复测](refined/C3.md)：把建筑对应特征与实际地名列为核心内容缺口，具体放到中段，不只反复宣布结果。仍需要使用者填实这些内容，不能当成直接可发布成稿。

这两份是规则定向修正后的新样例，不覆盖首次退步；没有再次运行C1初稿/C2或Kimi，故不能把局部结果扩大成全量通过。只读评审对补充C组的判断见盲评原文追加部分：C1局部改善但后半段仍有重复；C3未明显优于旧版，材料依赖清楚但需填实后才能兑现，不能把骨架写成已经完成的成片。

测试后仅把sources中的固定版本号改为指向入口元数据，避免每次版本变动产生出处说明矛盾；创作方法未因此改变。

## 怎样理解本轮

目标是让使用者更容易选方向、补一处关键材料、用自己的话接着写。包结构检查与模型表现分开；方法文本更清楚不等于所有模型更好。比较中存在执行者差异与有限样本，只能报告具体输出，不能证明优化因果或实际平台效果。

本机Codex已更新0.5.1，skills/list发现且enabled为true；一次读取安装入口的局部改写只交所需一句、未加载参考，符合小任务范围。这证明本机发现与一次调用，不代表全部创作质量。
