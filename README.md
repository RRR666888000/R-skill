# 凌酱 Skill｜短视频灵感与内容框架

[English](README.en.md) · [安装说明](docs/INSTALL.md) · [示例提示词](docs/EXAMPLES.md) · [测试与局限](tests/README.md)

**给想法找方向，把方向搭成你能继续写的骨架。** 面向所有短视频创作者，不限定行业、账号、风格或商业模式。“凌酱”是项目名称，使用不需要认识作者，也不需要他的私人资料。

当前方法版本 **0.5.2**。本版收紧单条视频的交付深度和与账号/制作类技能的路由边界，加入可复算的时长工具与跨宿主四层验收；0.5.1的[创意效用前后对照](tests/creative-051/README.md)仍保留优势、退步及已知失败。本次按维护者决定不处理既有P0事实保真问题，相关失败没有被删除或改称通过。

通常先给两三个真正不同的方向，说明谁可能想看、正文拿什么兑现，再推荐并展开一个具体骨架。你补充经历和自己的话；明确要完整稿时，它也可以写全文。它负责单条视频的文字内容；账号体系、个人IP或工作室规划、批量切片、实际拍剪及成片/数据复盘使用相应的编导、制作或分析流程。普通文章与纯转码不自动触发。

## 一分钟开始

第一次接触 Skill？可以把它理解为交给 AI 的一套工作方法。这不是独立软件，也不需要先学代码；你仍在自己的 AI 对话里提供素材、看方向和改稿。AI 产品本身的账号、费用和附件能力由对应产品提供。

**只想先试，不安装：** [下载通用单文件](https://raw.githubusercontent.com/RRR666888000/skills/main/dist/lingjiang-content.md)，上传给能读完整Markdown附件的Agent，再发：

> 请使用附件中的凌酱Skill。我的素材是【已知事实】，想做【时长、形式】的视频，目标是【希望观众得到什么/做什么】。给几个不同方向，你推荐一个展开骨架，我自己补充内容。缺少的经历不要编。

**支持导入技能包：** [下载技能ZIP](https://raw.githubusercontent.com/RRR666888000/skills/main/dist/lingjiang-content.zip)。它的根目录直接是`SKILL.md`，不是整个GitHub仓库压缩包。Claude Code、Codex等目录安装与WorkBuddy导入步骤见[安装说明](docs/INSTALL.md)。

安装后可说：`用凌酱Skill，帮我碰撞这条短视频的方向。` Claude Code也可用`/lingjiang-content`，Codex可显式用`$lingjiang-content`；命令是否提供由宿主决定。

如果下载链接打开了一屏文字，保存为 `.md` 文件后再上传，或复制完整内容；不要只给 AI 看文件名。附件无法完整读取时，改用支持文件的入口。想让 Agent 代安装，可直接复制[安装请求](docs/INSTALL.md#交给agent安装的一句话)。

## 第一次可以这样试

不需要准备复杂资料，先用这段虚构练习：

> 这是虚构练习，不是我的真实经历：有人连续三天拍同一扇窗，第一天晴天，后两天下雨。用凌酱Skill，只给两个短视频文字方向，各写观看理由和主要取舍，先不要展开骨架。

预期得到的是两个讲法及其差异，例如“同一位置的变化”和“重复观察的意义”；这是可能的方向举例，不是固定答案。然后可以接着说：

1. “选第二个，展开骨架。我还没定时长和形式，先别替我决定。”
2. “现在定为45秒口播，按这个骨架写完整稿，允许虚构，估计朗读时长。”
3. “只改第一句，让它更自然，不重贴正文。”

真实创作时，把练习换成你确认的素材，并说明哪些是事实、哪些只是想法。你也可以直接要全文；分步只是方便比较和修改。说“继续”会沿用当前交付范围，要进入全文时请明确说“写完整稿”。

## 它实际帮你做什么

| 你现在的需要 | 输出 |
|---|---|
| 只有零散材料 | 不同观看任务、主要取舍、能成立的方向与缺项 |
| 已选一个方向 | 各段具体讲什么、为什么接在这里、适合补什么材料 |
| 想到新事实 | 判断是否改变方向与结构，保留仍成立的事实 |
| 明确要全文 | 符合形式的稿件及可复算的估计时长；不逐段等确认 |
| 只改首句/某段 | 修改指定范围与必要衔接 |
| 只想审计 | 从实际内容信号推测停留、续看、看完与关注理由 |

不同方向需要不同的正文兑现，不能只是十个近义开头。默认不模仿作者或用户旧稿；你明确指定自己的样稿时，可以参考其表达特征。无口播作品不强加台词；没有变现计划也能开始。方法要求材料不足时明确缺项，不靠假经历撑满时长；实际模型仍可能不遵守，见下方实测边界。

## 能力边界

这是一套创作方法，不能预测流量或保证爆款。受众分析是有依据的假设，无法从文案准确推出年龄、收入或留存百分比。事实是否真实、片段实际怎样、成片节奏和最终发布效果仍需相应材料与验证。

跨Agent意味着相同的标准目录和文本方法可被支持它们的宿主读取；不意味着所有模型表现相同、所有产品已实测或每台电脑都已安装。当前Claude Code配置的`kimi-k2.6`已能原生调用，但稀少真实素材的多轮输出仍补造细节、心理或错误判断方法，尚未通过该项保真验收。请逐句核对要直接采用的事实及专业判断。Codex的有限回归结果不能证明其他模型同样可靠；所有失败首稿一并保留。见[测试记录](tests/README.md)。

## 文件怎么选

- `SKILL.md` + `references/`：标准目录版，按问题读取，适合原生支持Skill或能读目录的Agent。
- `dist/lingjiang-content.zip`：同一目录版的导入包。
- `dist/lingjiang-content.md`：完整单文件，适合附件或粘贴。整份输入会占用上下文；“按需取用”不会减少已经上传的文字量。
- `agents/openai.yaml`：可选Codex显示信息，其他Agent可忽略。
- `scripts/`：构建与校验工具，以及可选的确定性中文口播时长估算；普通创作不需要Python、MCP、密钥或其他Skill。英文或大量中英混排不能直接套用中文字符语速，优先实录或传入自行校准的口播单位数。
