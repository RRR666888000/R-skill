# 七词翻译链：从产品参数到消费者买点

## R — 原文 (Reading)

> “需求比方说你夏天通勤想要清清爽爽体体面面的到公司，这就是需求……痛点就是你害怕走到地铁口后背湿了一片，抬手有味道，你害怕的消费者害怕的那就是痛点。”
>
> — 直播电商基础课，00:00–01:43

> “卖点就是属性中的一部分，是由我们商家自己选出来的……价值就是我选中的卖点加上卖点对应的能给消费者带来的好处。”
>
> — 同上，02:38–03:45

## I — 方法论骨架 (Interpretation)

同一件产品，在消费者、产品、商家三个视角里有七种说法。消费者端是“我想要什么”（需求）和“我怕什么”（痛点），两者互为反面；产品端是“产品有什么”（属性）和“产品能带来什么”（功能）；商家端要主动做三件事：从属性里挑出目标人群关心的子集（卖点），把卖点翻译成消费者能感知的好处（价值），再叠加“为什么现在买”（买点）。

最关键的一条判定：**价值 = 卖点 + 消费者能感知的好处，不是卖点 + 功能**。“3 秒速干”是功能，“不粘身体”才是消费者能感到的好处；“316 不锈钢”是属性，“装热水到下午还烫嘴”才是价值。

这套链子是全课的语言地基。直播、短视频、详情页、贴片都讲价值；直播现场最常出现的是痛点、卖点、价值。话术没效果时，按四类排查：痛点不匹配（对象错了）、传递不到位（绕、缺因果）、未口语化（不像正常人说话）、信任被挡住（主播让人防御）。

## I-bis — 逐句判定树与高频歧义（审计用）

判定一句话属于哪一类，不看它用了什么词，而看它在整段话里**承担什么功能**：

1. **先分三层**：消费者端（需求/痛点）→ 产品端（属性/功能）→ 商家端（卖点/价值/买点）。
2. **再问三句**：
   - 主语是谁？消费者想要/害怕 → 需求/痛点；产品有/能做 → 属性/功能；商家选择/消费者得到 → 卖点/价值/买点。
   - 落点在哪？停在产品能力 → 功能；落到消费者结果 → 价值；落到“现在就买” → 购买动机（与价值合起来才是买点）。
   - 是全部还是选择？客观参数全集 → 属性；商家挑出来主打的少数几条 → 卖点。
3. **最后查歧义**：

| 原句 | 不要判成 | 应判成 | 理由 |
|---|---|---|---|
| “纯棉的” | 价值 | 属性（参数表）/ 卖点（主播主打时） | 只陈述材料，没有消费者结果 |
| “纯棉所以透气” | 价值 | 功能 | 停在产品能做什么 |
| “纯棉所以夏天不闷、不粘身” | 功能 | 价值 | 落到消费者能感知的结果 |
| “今天下单减 30” | 买点 | 购买动机（价格） | 没有价值，只是催化剂；与价值合起来才是买点 |
| “适合敏感肌” | 价值 | 卖点（人群选择） | 只圈人，没有说“所以你能得到什么” |
| “敏感肌也能安心用” | 卖点 | 价值 | 说出了消费者的具体结果 |
| “3 秒速干” | 价值 | 功能 | 产品能力，不是消费者结果 |
| “后背不湿” | 功能 | 价值 | 消费者能感知的结果 |

4. **输出判定表**：`原句 | 词类 | 判定依据 | 问题 | 改写`。每个最小句都要有词类；上下文不足时标“无法判定”，不硬贴标签。
5. **改写顺序**：属性→功能→价值→买点；需求/痛点先确认对象匹配，再讲卖点/价值。买点必须加真实动机，不编库存/原价/倒计时。

**特别注意**：同一句在不同语境可以判成不同词类。例如“聚酯纤维”在参数表是属性，在主播说“我特意选聚酯纤维，因为它凉感”时是卖点；判类必须以它在当前话术里的功能为准，并注明语境。

## A1 — 课程中的应用 (Past Application)

### 案例 1：速干衣的七层翻译（课程演示，未说明销售结果）

- **需求**：夏天通勤想清清爽爽、体体面面到公司。
- **痛点**：害怕走到地铁口后背湿一片、抬手有味道。
- **属性**：聚酯纤维、凉感面料、二本针领口、透气网孔、单向导湿、无感标。
- **功能**：吸湿排汗、3 秒速干、穿着舒服、骑车时有风穿过。
- **卖点**：商家选择“凉感面料、透气网孔、单向导湿”，不讲二本针和无感标。
- **价值**：采用单向导湿，内层疏水纱、外层亲水纱，所以吸湿排汗、3 秒速干、不粘身体。
- **买点**：价值 + “今天拍立减 30、前 500 送冰袖”。

课程明确对比了错误写法：只说“单向导湿、吸湿排汗、3 秒速干”，消费者仍想不到与自己有关；补上“不粘身体”才成立。

### 案例 2：面纸 FABE 练习（课程演示，未说明结果）

F=有保湿因子；A=别人家的面纸擦起来鼻子疼；B=春秋鼻炎高发期一直擦也不泛红；E=已卖很多、店铺分高、回购高、有保障。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 拿到一款产品，不知道怎么在直播/短视频里讲。
2. 写出来全是参数、材质、工艺，消费者没感觉。
3. 短视频/直播/详情页/贴片不知道各该放什么。
4. 话术发了没效果，需要判断是对象错了、表达绕了、还是不口语化。
5. 团队对“卖点、价值、买点”各说各话，需要统一口径。

### 语言信号

- “这个产品怎么讲/怎么提炼卖点”
- “我讲了材质和工艺，为什么没人买”
- “卖点和价值有什么区别”
- “详情页/贴片/短视频该写什么”
- “product messaging / value proposition / translate features into benefits”

### 与相邻 skill 的区分

- 与 `pfabes-scripting`：七词链负责“说什么”（内容语义），PFABES 负责“按什么顺序说”（直播结构）。
- 与 `purchase-motivation`：七词链走到“价值”为止；买点与“为什么现在买”交给购买动机。
- 与 `ren-huo-chang`：七词链是语言层；人货场是画面层。
- 与 `short-video-structure`：七词链产出价值句；短视频结构负责镜头与节奏。

## E — 可执行步骤 (Execution)

**输入契约**：产品全部参数、目标人群、一个具体使用场景。缺目标人群时先问一句“这东西主要卖给谁”，不要静默假设。

1. **写消费者端**
   - 需求：目标人群想要达到的状态。
   - 痛点：他们害怕发生的反面。
   - 完成标准：两句话都能让目标消费者说“对，就是我”。

2. **列产品端**
   - 属性：客观参数、材质、工艺、认证、规格。
   - 功能：这些属性让产品能干什么。
   - 完成标准：属性不夹带好处，功能不夹带消费者利益。

3. **选卖点**
   - 从属性里挑 1–3 个目标人群最关心的。
   - 完成标准：能说出“为什么选它、为什么不讲其余”。

4. **写价值句**
   - 句式：“因为[卖点]，所以[消费者能感知的好处]。”
   - 完成标准：消费者能接一句“这跟我有什么关系”，且答案是“有”。
   - 判停：如果只能接出功能，退回第 3 步重选卖点。

5. **加买点（可选）**
   - 只加真实、可解释的购买动机；没有真实动机就停在价值。
   - 完成标准：每个动机都能说出理由，不编库存/原价/倒计时。

6. **按渠道分配**
   - 直播现场：痛点、卖点、价值；短视频/详情页/贴片：价值优先。
   - 完成标准：每个渠道至少有一句价值句，不铺参数。

7. **无效时诊断**
   - 依次查：对象是否匹配 → 表达是否绕 → 是否口语化 → 信任是否被挡。
   - 完成标准：能定位到一类，并给出改写句。

**输出契约**：一张七层表（需求/痛点/属性/功能/卖点/价值/买点）+ 至少 3 条可直接使用的话术 + 一句“这跟我有什么关系”的验证记录。

## B — 边界 (Boundary) ★

### 不要在以下情况使用

- 纯参数查询、比价、招标文件：不需要翻译成消费者语言。
- 目标人群尚未确定：先做 `eight-audience-segments`，否则七词链会写成自嗨。
- 产品本身没有真实差异：不要用话术补造卖点；先回到产品/供应链。

### 作者警告的失败模式

- 把功能当价值：“吸湿排汗、3 秒速干”与消费者无关。
- 卖点堆砌：属性全讲一遍，消费者什么都记不住。
- 痛点不匹配：把电商课卖给根本不打算做电商的人。
- 不口语化：满嘴“哥哥姐姐”“番茄炒蛋吗”，不像正常人说话。
- 信任被挡：主播油腔滑调、半死不活，消费者先防御。

### 作者盲点 / 时代局限

- 课程假设“讲清价值就会买”，忽略了价格、流量、信任、售后等变量。
- 七词链对低决策成本商品很有效；对高客单、B2B、需要长期教育的产品，需要更长的证据链。
- “买点”只取催化剂型是作者的简化，完整购买动机还有理由型（痛点/价值），见 `needs-review.md`。

### 容易混淆的邻近方法论

- `pfabes-scripting`：同样讲 F/B，但它是直播话术的模块与顺序，不负责从产品参数里提炼语义。
- `purchase-motivation`：负责“现在买”，不负责“这东西对我有什么用”。
